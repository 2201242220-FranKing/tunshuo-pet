二、仍需确认（按优先级）

1. 完整学校 circleId 对照表 + 长征圈子核对（最需要）
   桌宠现在支持同时监控多个学校。用户已给 4 个 ID，我们逐个匿名联调（2026-11-11）：
     浙外   1844924022131912706  -> 回读「浙外校友圈」   recordsTotal 7637  正常
     浙工大 1849752540716011521  -> 回读「浙工大校友圈」 recordsTotal 7295  正常
     浙科   1846842931990769666  -> 回读「浙科校友圈」   recordsTotal 12152 正常
     长征   1860950189561458688  -> data=[] / recordsTotal=0   ⚠ 无帖子
   长征这个 ID 用 /app/dynamic/page 带 circleId 读取，code=200、message=请求成功，
   但三种参数（type=dynamic / 不带 type / type=all）都返回空数组。请确认：
     a) ID 是否写错，或该圈子已停用/还没开放发帖；
     b) 若确为正常空圈子，我们保留在监控列表里，之后有新帖会自动出现。
   另请给完整的「学校名称 / 简称 -> circleId」对照表，最好有接口能一次拿到
   「全部学校圈子列表」（含 id 与名称），这样我们不用逐个手工登记。
   不传 circleId 时接口会返回全站数据，我们不想默认这么做。

2. 十大热帖、新帖数接口需要登录态（最关键）
   GET /app/dynamic/ten/page?circleId=...
   GET /app/dynamic/new/num?circleId=...&time=...&type=dynamic
   两者都返回 {"code":110, "message":"请先登录", "data":null}。
   请二选一：
   a) 提供匿名只读入口（推荐。桌宠是本地常驻程序，不希望长期保存用户登录态）；
   b) 说明 token 的获取方式、放在哪个 Header、有效期与刷新方式。
   在确认前，桌宠会自动降级为「最新帖按 totalHeatNum 降序出榜」，
   新帖播报不受影响，只是拿不到全站十大。

3. 站内信 / 未读消息的正确路径
   上一版文档里「十大热帖」和「站内信 提醒未读消息」写成了同一个
   GET /app/dynamic/ten/page?circleId=，疑似复制粘贴漏改。
   请给正确路径、参数与返回字段（未读数是纯数字还是对象、字段名）。
   桌宠目前没有站内信角标 UI，确认后再评估要不要做。

4. 打开原帖的 H5 链接规则
   帖子接口没有返回任何 url 字段，桌宠双击热帖榜现在无法跳转。
   请给拼接模板，例如 https://xxx/h5/dynamic/detail?id={id}；
   若没有网页版，请说明，我们改成客户端内弹详情（用 /app/dynamic/detail）。

5. 次要项（有空再给，不阻塞）
   - /app/dynamic/new/num 的 time 语义：时区、按 createTime 还是 updateTime 比较、
     首次拉取传什么、返回纯数字还是对象。
   - tagId 的枚举从哪个接口拿。
   - pageSize 上限与限频；桌宠默认不自动轮询，目前手动刷新，
     每所学校每次最多拉 20 条，当前监控 4 所学校 = 一次刷新约 4 个只读请求
     （实测约 6 秒；空圈子响应偏慢）。若以后打开定时轮询（默认 3 分钟一次），
     或学校数增加到 N 所，一次会发 N 个（上限 20 个）请求，
     请确认这个频率是否可接受。


三、我们这边的约定
- 令牌只从环境变量临时读取，绝不写进会入库的配置文件。
- 自动轮询默认关闭，接好接口后仍先由用户手动点「立即刷新」。
- 当前登记 4 所学校（上限 20 所）；逐校拉取、合并去重、失败互不影响。
- 若接口字段变动，只需改字段映射表，不需要改桌宠逻辑。
